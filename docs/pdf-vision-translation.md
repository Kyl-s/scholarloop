# PDF 视觉翻译路线

## 桌面更新方式

Electron 桌面由本地后端托管 `dist`，不是 Vite 热更新页面。修改前端源码后，已经打开的窗口不会自动应用；需从系统托盘彻底退出 ScholarLoop 再启动，启动过程会检查源文件并按需重建。仅关闭窗口可能只是隐藏到托盘。后端改动同样需要重启进程，不要以当前窗口仍在运行作为新代码已加载的证据。

## 两类输出不能混为一谈

- **原版式译文**：现有 PDFMathTranslate/BabelDOC 链路生成 PDF，适合保留原页结构；复杂公式、跨栏和中文扩张仍可能造成漏译或重排问题。
- **视觉精读**：将当前页截图与可提取文本交给支持图片的模型，按阅读顺序返回完整段落、标题、图注、公式和表格文本。译文可按段落区域覆盖显示，侧栏保留完整结果，不把中文强塞回英文行框。这是阅读显示层，不会改写原 PDF 文件，也不是保真 PDF 导出。

视觉请求仅由用户主动触发；截图和当前页文字会发送至当前配置的模型服务。扫描页也可请求，但识别不清必须提示，不能补写内容。公式独立呈现，表格使用文本表达，原始 PDF 保留作为核对依据。模型不支持图片时应明确报错，不静默退化为“识图成功”。

视觉翻译是默认工作流，阅读区上方显示紧凑控制条及“新工作台”标识；结果详情放在侧栏，其他方式统一放在“更多翻译方式”。可选择当前页、页码范围（如 `1-5,8`）或全文，显示文档总页数、累计完成数和本次进度。点击开始后按页串行调用，跳过已完成页；取消或失败停止后续请求并保留完成结果，翻页可查看对应译文。切换文档或模型会停止任务；收起详情侧栏不会中断翻译。结果只在当前运行内存缓存，刷新或重新加载文档可能丢失；已发送请求仍可能计费。HTTP 402 单独提示检查模型服务余额、额度或付费权限，不等同于 OAuth 失效。

原版式输出的后处理必须保守：原书页号与单页产物页号不同；正文中含行内公式不等于整行应该保留英文；不可用跨栏大矩形回贴原文去擦除正常译文。生成策略升级应更换任务身份，历史译文只读恢复仍应允许。

## 视觉段落覆盖边界

请求的 `layoutVersion: 1` 携带截图同一 viewport 的行锚点 `lines: [{index,text,bbox}]`。bbox 为左上原点、横纵各归一化到 0..1000 的 xyxy。模型返回段落 `lineIndexes`，有文本层时从真实行框计算候选区域；扫描页可返回候选 bbox 与 confidence。旧的无定位结果只能侧栏阅读，需要用户手动重译以获取坐标，不额外自动调用模型。

`overlaySafe` 只是必要条件，不是无条件涂白授权。重复占行、明显跨栏、不可靠坐标、公式、表格以及含行内公式的段落不得整块覆盖。前端还需测量自然换行后的尺寸；正常字号下放不下时保留原页并提示侧栏查看。图表保持原图，不能保证图内文字替换。视觉译文须以原始页为底图，不可叠在历史 PDFMath 译文 PDF 上。

### 覆盖失败的局部降级

文字翻译完成、段落可定位、页面实际覆盖是三个不同状态。不得把“已翻译但覆盖零段”标成页面覆盖成功。一个公式未定位或一个页边字符坐标异常，不应自动否决所有正文段落；应保留危险区域的局部碰撞证据，按段落判断。前后端覆盖类型、数学识别和扫描置信度使用同一策略，字号随页面缩放，避免缩小时固定像素下限造成整页不覆盖。已有定位结果的重新排版应在本地完成，不额外请求模型；无定位的历史结果才需要手动重译。

## 开源方案调研（2026-10-28）

| 项目 | 适用方向 | 集成注意 |
| --- | --- | --- |
| [PDFMathTranslate-next](https://github.com/PDFMathTranslate/PDFMathTranslate-next) / [BabelDOC](https://github.com/funstory-ai/BabelDOC) | 原版式和双语 PDF | AGPL-3.0 系列。BabelDOC 当前推荐通过 next 接入，不能假定内部 Python API 稳定。当前保留现有引擎，不直接复制其代码。 |
| [Docling](https://github.com/docling-project/docling) | 可选结构化解析、OCR、表格和公式 | 代码 MIT，模型需单独核对许可；不是保真翻译 PDF 渲染器。 |
| [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) | 可选扫描与细粒度坐标解析 | Apache-2.0 项目，需评估运行时与模型打包成本。 |
| [Tesseract.js](https://github.com/naptha/tesseract.js) | 无 Python 的基础扫描文字补救 | Apache-2.0；必须先渲染 PDF 成图片，不提供公式或图表语义理解。 |

优先复用已有模型和 PDF 渲染能力，避免为改善阅读体验强制引入 Docker、GPU 或新的重量级常驻服务。视觉精读是独立实现的结构化输出路线，并未引入上表的新依赖。子进程或 HTTP 隔离并不自动免除 AGPL 合规义务；若进一步分发、修改或集成引擎，需要评估实际许可责任。
